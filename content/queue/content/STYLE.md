# 원고 작성 규칙

새 원고를 쓸 때는 이 문서와 `content/queue/001-attention.json`을 함께 읽고 그 형식을 따르세요.

## 파일

- 경로: `content/queue/NNN-슬러그.json` (예: `002-positional-encoding.json`)
- 번호는 3자리, 큐는 **파일명 순서대로** 발행됩니다.
- `series_no`는 파일 번호와 일치시킵니다.
- 핸들·시리즈명은 원고에 쓰지 않습니다. 루트 `config.json`에서 한 번만 관리합니다.

필수 키: `series_no`, `topic`, `cards`, `caption`, `hashtags`

## 카드 구성 — 정확히 10장

인스타그램 캐러셀 API 상한이 10장입니다. 11장 이상은 잘립니다.

| 순서 | type | 역할 |
|---|---|---|
| 1 | `cover` | 후킹 질문형 제목 |
| 2–8 | `visual` 중심, `body` 보조 | 입문자용. 문제 제기 → 아이디어 → 구조 → 계산 → 의미 → 확장 |
| 9–10 | `insight` | 실무자용. 비용·함정·실전 판단 기준 |

**2–8번 중 최소 4장은 `visual`로 만드세요.** 글만 이어지면 스크롤이 멈춥니다.

## visual 카드

```json
{"type":"visual","kicker_label":"실측","heading":"짧은 제목",
 "lead":"(선택) 그림 위 한 문장",
 "visual":{"kind":"bars", ...},
 "caption":"그림 아래 한두 문장. 그림이 뭘 말하는지 해석해 줍니다."}
```

`kind`는 여섯 가지입니다.

| kind | 언제 | 필수 필드 |
|---|---|---|
| `flow` | 파이프라인·단계 | `steps:[{label,sub,highlight}]`, `direction:"h"|"v"` |
| `bars` | 수치 비교 | `items:[{label,value,highlight}]`, `max`(눈금 상한) |
| `line` | 추세·곡선 | `series:[{label,points:[[x,y]…]}]`, `xlabel`, `ylabel` |
| `heatmap` | 여러 대상 × 여러 지표 | `rows`, `cols`, `values`, `normalize:"col"` |
| `compare` | 둘의 대비 | `left/right:{title,items:[…]}` |
| `formula` | 수식 각 항 설명 | `parts:[{text,note,color}]` |

규칙 몇 가지.

- `bars`에는 **반드시 `max`를 지정**하세요. 없으면 눈금이 자동으로 잡혀 차이가 과장됩니다.
- `heatmap`에서 지표마다 값의 범위가 다르면 `"normalize":"col"`을 쓰세요. 안 쓰면 전부 비슷한 색으로 뭉갭니다.
- `flow`는 가로 4단계, 세로 3단계까지가 깔끔합니다. `label`은 6자 이내, `sub`는 한 줄.
- `compare`의 `items`는 한 줄에 20자 이내, 3~4개.
- 강조하고 싶은 한 곳에만 `highlight: true`를 씁니다. 두 곳 이상 쓰면 강조가 죽습니다.
- **출처가 특정 실험이면 `caption`에 "한 실습 데이터셋 기준"처럼 범위를 밝히세요.** 일반화된 벤치마크인 것처럼 쓰면 안 됩니다.

10번 카드에는 반드시 `cta`로 다음 편 예고 + 저장 유도를 넣습니다.

## 톤

- 존댓말, 단정한 설명체. 광고 문구처럼 들리지 않게.
- 과장 금지. "혁명", "충격", "미쳤다" 같은 단어는 쓰지 않습니다.
- 이모지는 쓰지 않습니다.
- 한 카드에 개념 하나. 두 개를 욱여넣지 않습니다.

## 분량 (넘치면 자동 축소되지만, 작아지면 가독성이 떨어집니다)

- `heading`: 12~22자. 한 줄이나 두 줄에 떨어지게.
- `body`: 2~4문장, 총 90~150자. 문단은 `\n`으로 나눕니다.
- `note.text`: 40~80자.
- `bullets`: 2~3개, 각 45~90자.
- `cta`: 50~80자.

## 인라인 마크업

- `**강조**` → 흰색 굵은 글씨
- `` `코드` `` → 파란 코드 칩
- 수식은 유니코드로 씁니다: `softmax(QKᵀ / √dk)`, `O(n²)`

## 정확성 규칙 — 가장 중요

- 논문을 인용할 때는 **저자 성 + 연도**만 씁니다 (예: `Vaswani et al., 2017`).
  기억이 확실하지 않으면 인용을 아예 빼세요. 틀린 인용이 없는 인용보다 나쁩니다.
- 숫자(파라미터 수, 벤치마크 점수, 발표 연도)는 확실한 것만 씁니다.
- 논쟁 중인 주제는 "논쟁 중"이라고 명시합니다. 한쪽 결론으로 단정하지 않습니다.
- 특정 회사 모델의 최신 스펙은 바뀌므로 카드에 박아넣지 않습니다.

## 비유

2번 카드 근처에 일상 비유를 하나 넣으면 저장률이 오릅니다. 단, 비유가 개념을
왜곡하면 넣지 않는 편이 낫습니다. 비유 뒤에는 반드시 실제 메커니즘을 붙입니다.

## 캡션

- 3~4문단. 첫 문장이 미리보기에 노출되므로 가장 중요한 한 줄을 맨 앞에.
- 마지막에 다음 편 예고 + 저장 유도.
- `hashtags`는 20~25개. 대형 태그(#인공지능)와 소형 태그(#어텐션메커니즘)를 섞습니다.
- 시리즈 고정 태그: `#인공지능 #AI #머신러닝 #딥러닝 #AI이론 #AI공부`

```bash
cd scripts && python render.py --slug 002-positional-encoding
```
